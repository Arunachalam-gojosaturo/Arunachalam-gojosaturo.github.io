How I Built ArcXOS: Designing a Security-Focused Arch Linux Distro

DATE: August 1, 2026
READ TIME: 12 min read
AUTHOR: Arunachalam M

A comprehensive architectural breakdown of creating ArcXOS using archiso, custom PKGBUILD repositories, automated system hardening scripts, and developer-first dotfile environments.

Introduction: The Philosophy Behind ArcXOS

As an Arch Linux developer and system administrator based in Vellore, Tamil Nadu, I’ve long admired the DIY philosophy of Arch Linux: minimalist, rolling-release, and completely transparent. However, setting up a fresh Arch installation optimized for cybersecurity auditing, penetration testing, and AI infrastructure development manually takes hours of package installation, configuration tweaking, and dotfile synchronization.

I engineered ArcXOS to eliminate this initial friction while preserving the raw power of Arch. ArcXOS is not a heavy desktop fork; it is a refined, security-hardened Arch Linux distribution tailored for developers, security researchers, and power users who need an out-of-the-box system with modern kernel optimizations and pre-configured terminal ergonomics.

1. The Build Pipeline: Archiso Architecture

At the core of ArcXOS is a custom build pipeline leveraging archiso, the official Arch Linux ISO generation toolchain. The build process constructs a bootable live environment containing custom pacman repositories, systemd services, and customized desktop environments (Hyprland / Wayland).

# Directory structure of the ArcXOS build system
arcxos-build/
├── profiledef.sh          # ISO release metadata & filesystem compression settings
├── packages.x86_64        # List of explicit packages (hyprland, netwatch, cyberkit, linux-zen)
├── pacman.conf            # Custom pacman configuration including ArcXOS mirrors
├── airootfs/              # Filesystem overlay placed on top of base install
│   ├── etc/
│   │   ├── sysctl.d/99-arcxos-security.conf
│   │   ├── systemd/system/netwatch.service
│   │   └── skel/          # Default user configuration files (.zshrc, .config/hypr)
│   └── usr/local/bin/
└── syslinux/              # Bootloader configuration for live USB drives

Configuring profiledef.sh

In profiledef.sh, we define the SquashFS compression settings and file permissions for live booting:

#!/usr/bin/env bash
# ArcXOS profile definition
iso_name="ArcXOS"
iso_label="ARCXOS_$(date +%Y%m)"
iso_publisher="Arunachalam M "
iso_application="ArcXOS Arch Linux Security & Developer Distro"
iso_version="$(date +%Y.%m.%d)"
install_dir="arch"
buildmodes=('iso')
bootmodes=('bios.syslinux.mbr' 'bios.syslinux.eltorito' 'uefi-x86_64.systemd-boot.esp')
arch="x86_64"
pacman_conf="pacman.conf"
airootfs_image_tool_options=('-comp' 'xz' '-b' '1024K' '-Xbcj' 'x86')

2. Security Hardening & Kernel Customization

Standard Linux distribution kernels prioritize generic hardware compatibility over tight security boundaries. ArcXOS defaults to the linux-zen or linux-hardened kernel profiles, paired with aggressive kernel runtime parameters applied during boot.

Kernel Runtime Hardening Configuration

Every ArcXOS installation automatically applies kernel self-protection parameters in /etc/sysctl.d/99-arcxos-security.conf:

# Restrict unprivileged access to kernel logs
kernel.dmesg_restrict = 1

# Restrict kptr leaks in /proc
kernel.kptr_restrict = 2

# Harden BPF JIT compiler
net.core.bpf_jit_harden = 2

# Enable Reverse Path Filtering to prevent IP spoofing
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1

# Disable ICMP redirect acceptance
net.ipv4.conf.all.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0

# Enable ASLR (Address Space Layout Randomization)
kernel.randomize_va_space = 2

3. Pre-Integrated Defensive Tools: Cyberkit & Netwatch

Unlike general-purpose distributions that require manual AUR compilation, ArcXOS comes pre-loaded with my open-source defensive security tools:

  • Cyberkit: A 22-in-1 pure Bash audit engine that scans for SUID root vulnerabilities, modified system files, world-writable directories, and Lynis security compliance scores.
  • Netwatch: A real-time socket monitoring tool that tracks active TCP/UDP connections and flags suspicious outbound traffic directly in the terminal.
