Introduction: The Quest for Reliable AI Agents

Most commercial AI assistants are constrained by single-cloud API vendor lock-in, rigid chat UIs, and fragile function calling. When a third-party API rate-limits your key or experiences downtime, your autonomous agent collapses. I built Luna AI to solve this foundational reliability problem.

Luna AI is a modular, self-healing desktop AI assistant and agent framework built in Python and FastAPI. It features zero-downtime multi-provider failover (Groq, Ollama, OpenRouter, Anthropic, local models), persistent vector memory, and asynchronous tool execution.

1. The Multi-Provider Failover Architecture

At the heart of Luna AI is an intelligent provider fallback dispatcher. If the primary cloud provider (e.g. Groq Llama-3) returns a 429 Rate Limit error or experiences a high latency threshold (>1200ms), Luna AI instantly reroutes the prompt payload to a local Ollama instance or secondary cloud provider without losing conversation state.

# Python LLM Failover Dispatcher in Luna AI Core
import asyncio
import logging
from typing import List, Dict, Any, Optional

logger = logging.getLogger("LunaCore.Dispatcher")

class LLMProvider:
    def __init__(self, name: str, api_key: str, endpoint: str):
        self.name = name
        self.api_key = api_key
        self.endpoint = endpoint

    async def check_health(%) -> bool:
        # Pings endpoint to confirm responsiveness
        return True

    async def generate(self, prompt: str, tools: List[Dict[str, Any]]) -> str:
        raise NotImplementedError

class LunaDispatcher:
    def __init__(self, providers: List[LLMProvider]):
        self.providers = providers

    async def execute_query(self, prompt: str, tools: List[Dict[str, Any]]) -> str:
        for provider in self.providers:
            try:
                logger.info(f"Attempting inference via provider: {provider.name}")
                if await provider.check_health():
                    response = await asyncio.wait_for(provider.generate(prompt, tools), timeout=5.0)
                    return response
            except Exception as exc:
                logger.warning(f"Provider {provider.name} failed with error: {exc}. Trying fallback...")
        
        raise RuntimeError("CRITICAL: All LLM inference providers are currently unreachable.")

2. Autonomous Tool Dispatching & Agent Execution Loop

Luna AI uses a finite state machine (FSM) loop to handle autonomous tool execution. When Luna determines that an operation requires external input (e.g., reading a file, executing a shell command, checking network traffic), it generates structured tool calls that pass through a sandboxed execution engine.

# Agent execution state machine loop
async def agent_loop(user_input: str):
    context = await memory_store.retrieve_context(user_input)
    messages = context + [{"role": "user", "content": user_input}]
    
    while True:
        response = await dispatcher.execute_query(messages, available_tools)
        if response.has_tool_call:
            tool_name = response.tool_name
            tool_args = response.tool_args
            
            # Execute tool in isolated async task
            result = await execute_sandboxed_tool(tool_name, tool_args)
            messages.append({"role": "tool", "name": tool_name, "content": result})
        else:
            # Final text response generated
            await memory_store.save(user_input, response.text)
            return response.text

3. Local RAG & Vector Memory with FAISS

To enable long-term memory across system restarts, Luna AI indexes local developer documentation and conversation logs using local sentence-transformers embeddings coupled with a high-speed FAISS (Facebook AI Similarity Search) vector store.
